# UI Conventions

편집 UI를 만들거나 리뷰할 때 쓴다.

## 컴포넌트

- TypeScript 함수 컴포넌트. 컴포넌트는 `PascalCase`, 헬퍼는 `camelCase`.
- props는 `interface`로 타입 지정한다. 공유 타입은 소유자 쪽에 둔다 — 곡 데이터 타입(`Note`, `Track`, `Pattern`)은 `lib/score/`에서, 엔진 타입은 `lib/audio/`에서, UI 컨텍스트 타입(`StudioApi` 등)은 `state/types.ts`에서 export한다.
- 새 패턴을 도입하기 전에 주변 컴포넌트 스타일을 먼저 맞춘다.

## 스타일

- Tailwind CSS 4. 클래스 문자열을 직접 쓴다. `cn()` 헬퍼도 컴포넌트 라이브러리도 없다 — 추가하지 않는다. 필요하다고 판단되면 먼저 사용자에게 묻는다.
- 숫자 표시(BPM, 마디:박, 시간)는 `font-mono tabular-nums`. 폭이 변하면서 레이아웃이 흔들리는 걸 막는다.
- 설명용 문구를 화면에 임의로 추가하지 않는다. 요청이 있을 때만 넣는다.

### 팔레트

타임라인 화면에서 정한 값이다. 이후 화면은 여기 맞춘다. 라이트 테마는 없다 — 긴 시간 응시하는 도구이고 타일 색 구분이 중요해서다.

| 용도 | 값 |
| --- | --- |
| 앱 배경 | `#0b0c0f` (`app/globals.css`의 `body`) |
| 패널 — 헤더 바, 트랙 헤더 열 | `#141519` |
| 패널 경계 | `border-white/10` |
| 행 구분선 | `rgb(255 255 255 / 0.07)` |
| 마디선 / 박선 | `white/0.11` / `white/0.035` |
| 본문 텍스트 | `text-zinc-200` · 보조 `text-zinc-400` · 흐림 `text-zinc-500` |
| 플레이헤드 | `bg-red-500` |

악기 색은 클립 타일과 트랙 헤더 점이 같은 계열을 쓴다(`components/studio/instruments.ts`): 피아노 `indigo`, 기타 `emerald`, 베이스 `amber`, 드럼 `rose`. 타일은 `bg-{색}-500/25` + `border-{색}-400/60`.

### 레이아웃

- 앱 셸은 `h-dvh`로 화면을 꽉 채우고 바깥(`body`)은 스크롤하지 않는다. **세로 스크롤 소유자는 `body-scroll` 래퍼 하나**이고, 그 안의 헤더 열과 타임라인은 같은 행에서 함께 늘어난다(`body-columns`, `flex min-h-full`). 타임라인(`timeline`)은 `overflow-x-auto overflow-y-hidden`이라 가로만 스크롤한다 — 세로 스크롤러를 중첩하면 헤더 열과 어긋난다. 가운데 정렬된 `max-w-*` 칼럼을 두지 않는다 — DAW는 화면을 다 쓴다.
- 스테이지에 `min-h-full`과, 마디 컨트롤 폭을 뺀 `minWidth`(`calc(100% - BARS_CONTROL_WIDTH)`)를 준다. 곡이 뷰포트보다 짧아도 격자가 화면을 채우고 마디 ±버튼이 화면 안에 남는다.
- **행 구분선은 `border`가 아니라 `boxShadow`(inset)로 그린다.** border는 박스 높이를 1px 먹어서, 드럼 라인처럼 안쪽 행 높이의 합이 컨테이너 높이와 같아야 하는 경우 헤더 열과 스테이지가 아래로 갈수록 어긋난다. 상수는 `components/studio/layout.ts`의 `ROW_DIVIDER`.
- 트랙 헤더 열과 스테이지는 같은 높이 상수(`components/studio/layout.ts`)를 쓴다. 스테이지 맨 위 눈금자 높이만큼 헤더 열에도 빈 칸을 둔다.
- 스크롤 영역에는 `.timeline-scroll` 클래스를 붙인다(`app/globals.css`). 기본 스크롤바는 어두운 스테이지 위에서 혼자 튄다. **스크롤바를 직접 만들지 않는다** — 휠·트랙패드·키보드·접근성을 전부 다시 만들어야 한다.

## 피아노롤 / 타임라인

노트가 수천 개까지 갈 수 있는 화면이다. 일반 폼 UI와 규칙이 다르다.

- **플레이헤드는 노트와 분리된 레이어**로 그린다. 플레이헤드가 움직일 때 노트 컴포넌트가 리렌더되면 안 된다. `transform: translateX()`만 바꾸고, 값은 `requestAnimationFrame`에서 ref로 직접 쓴다 — `useState`를 거치지 않는다.
- 노트 렌더 방식(DOM 요소 vs `<canvas>`)은 아직 정해지지 않았다. DOM으로 시작하되 노트 수가 늘어 프레임이 떨어지면 canvas로 옮긴다. 어느 쪽이든 화면 밖 노트는 그리지 않는다(가상화).
- 그리드 계산은 음악적 시간 기준이다. 픽셀 좌표는 렌더 직전에 `pixelsPerBeat × zoom`으로 환산한다. 노트 데이터에 픽셀 값을 저장하지 않는다.
- 줌·스크롤 상태는 React 상태로 둬도 된다(사용자 조작 빈도라서). 단 스크롤 중 매 이벤트마다 전체 리렌더가 나지 않는지 확인한다.

## 인터랙션

- 드래그·리사이즈는 `pointerdown` → `pointermove` → `pointerup` 흐름으로 처리하고, `setPointerCapture`로 요소 밖으로 나가도 추적이 끊기지 않게 한다. **캡처는 `pointerdown`에서 잡는다. 드래그 임계값을 넘길 때까지 기다리지 않는다** — 마우스는 암묵적 캡처가 없어서, 임계값 뒤에 잡으면 8px 핸들이나 클립 가장자리에서 빠르게 끌 때 포인터가 이미 요소 밖이라 `move`·`up`을 못 받아 드래그가 시작조차 못 한다. 캡처 실패(`setPointerCapture`가 던짐)면 제스처를 만들지 않는다. 클릭과 드래그는 놓을 때 정한다(5px 이내면 클릭).
- 드래그 중에는 미리보기만 갱신하고, 실제 곡 데이터 커밋은 `pointerup`에서 한 번만 한다. 드래그 매 프레임마다 `setState`로 곡 전체를 갈아치우지 않는다.
- 키보드 단축키(스페이스=재생/정지 등)는 입력 필드에 포커스가 있을 때 가로채면 안 된다. 핸들러에서 `event.target`을 확인한다. 이미 `defaultPrevented`인 이벤트는 무시한다.
- **`Esc` 한 번은 한 겹만 닫는다**: 진행 중인 드래그 → 열린 팝오버 → 선택 순서다. 드래그·팝오버는 `document`의 캡처 단계 리스너에서 처리하고 `preventDefault()`로 표시하며, 선택 해제(버블 단계, `useShortcuts`)는 `defaultPrevented`면 건너뛴다.
- **소리를 내는 모든 진입점은 사용자 제스처 안에 있어야 한다.** 재생 버튼, 건반 클릭, 노트 미리듣기 핸들러에서 `AudioContext.resume()`이 보장되는지 확인한다 (`.claude/rules/audio-engine.md` 참고).
- 포인터로 시작한 조작에는 **취소 경로**를 둔다. `pointercancel`·`lostpointercapture`(놓기 없이)·`Esc`·편집 불가로 바뀜·언마운트에서 미리보기를 되돌리고 상태를 비운다. 없으면 터치 패닝이나 요소 언마운트로 `pointerup`이 안 와서 DOM에 쓴 미리보기가 남고, React가 소유한 속성이면 다시 쓰이지 않아 영구히 굳는다. 포인터로 끄는 요소에는 `touch-action: none`을 준다.
- `pointerdown`은 우클릭에도 온다. 편집을 시작하는 핸들러는 `event.button !== 0`이면 일찍 반환한다.
- **DOM에 직접 쓴 미리보기를 `""`로 지우지 않는다.** React가 그 속성을 소유하고 있으면 React의 스타일 기록과 어긋나 다음 렌더에서 같다고 판단해 다시 쓰지 않는다. 시작 시점의 문자열을 저장해 그대로 되돌린다.

구현된 편집 제스처(`components/studio/`):

| 제스처 | 결과 |
| --- | --- |
| 트랙 레인 빈 곳 클릭 | 눌린 자리가 든 반마디(960틱) 칸의 시작에 기본 1마디 클립을 만들고 선택한다. 이웃·곡 끝까지 공간이 모자라면 반마디 단위로 줄고, 반마디도 없으면 아무 일 없다 |
| 클립 클릭 | 선택. 패턴 클립이면 패턴 팝오버(패턴 고르기, "이 트랙 전체에 적용")도 연다. `notes` 클립은 팝오버가 없다 |
| 클립 본문 드래그 | 이동. 5px부터 드래그로 본다. 스냅 960틱, 이웃 클립과 곡 끝에서 클램프. 놓을 때 한 번 커밋 |
| 클립 오른쪽 가장자리(8px 핸들) 드래그 | 길이 조절. 같은 스냅·클램프, 최소 반마디 |
| 선택된 클립의 × | 삭제 |
| 코드 구간 클릭 | 코드 팝오버(근음 12 × 종류 5, "가운데에서 나누기", "오른쪽과 합치기") |
| 코드 구간 경계(8px 핸들) 드래그 | 경계 이동. 스냅, 양쪽 구간 반마디 이상으로 클램프 |
| `Esc` | 한 번에 한 겹: 드래그 취소 → 팝오버 닫기 → 선택 해제 |
| `Space` | 재생/정지. 입력·링크·`select`와, 키보드로 포커스된(`:focus-visible`) 버튼 위에서는 네이티브 동작에 양보 |
| `Ctrl`/`Cmd`+`Z` | 되돌리기(드래그 중에는 무시) |
| `Delete` / `Backspace` | 선택한 클립 삭제(팝오버·텍스트 입력 안에서는 무시) |

편집은 정지 중에만 동작한다. `useStudio().editable`은 `!playing && !pending`이다(`pending` = `play()`가 컨텍스트 재개·샘플 준비를 기다리는 중). 재생 중에는 편집 컨트롤이 비활성(`aria-disabled` 또는 `disabled`)이 되고 "재생 중에는 편집할 수 없습니다"가 표시된다.

## 접근성

- 재생/정지, 트랙 뮤트/솔로 같은 컨트롤은 실제 `<button>`이어야 한다. `<div onClick>`으로 만들지 않는다.
- 노트 그리드 자체는 키보드로 다루기 어렵다. 최소한 트랜스포트 컨트롤과 트랙 목록은 탭 순서가 통하게 한다.
- 색만으로 상태를 구분하지 않는다(뮤트된 트랙, 선택된 노트 등).

## 검증

- `pnpm dev`로 실제로 띄워 본다. diff는 화면이 어떻게 보이는지 알려주지 않는다.
- 노트를 많이 배치한 상태에서 스크롤·줌·재생이 부드러운지 본다.
- 좁은 화면과 넓은 화면 양쪽에서 트랙 헤더와 타임라인이 어긋나지 않는지 본다.
