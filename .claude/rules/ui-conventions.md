# UI Conventions

편집 UI를 만들거나 리뷰할 때 쓴다.

## 컴포넌트

- TypeScript 함수 컴포넌트. 컴포넌트는 `PascalCase`, 헬퍼는 `camelCase`.
- props는 `interface`로 타입 지정한다. 공유 타입은 소유자 쪽에 둔다 — 곡 데이터 타입(`Note`, `Track`, `Pattern`)은 `lib/score/`에서, 엔진 타입은 `lib/audio/`에서, UI 컨텍스트 타입(`StudioApi` 등)은 `state/types.ts`에서 export한다.
- 새 패턴을 도입하기 전에 주변 컴포넌트 스타일을 먼저 맞춘다.

## 스타일

- Tailwind CSS 4. 클래스 문자열을 직접 쓴다. `cn()` 헬퍼도 컴포넌트 라이브러리도 없다 — 추가하지 않는다. 필요하다고 판단되면 먼저 사용자에게 묻는다.
- 숫자 표시(BPM, 마디:박, 시간)는 `font-mono tabular-nums`. 폭이 변하면서 레이아웃이 흔들리는 걸 막는다.
- 설명용 문구를 화면에 임의로 추가하지 않는다. 요청이 있을 때만 넣는다.

### 팔레트

타임라인 화면에서 정한 값이다. 이후 화면은 여기 맞춘다. 라이트 테마는 없다 — 긴 시간 응시하는 도구이고 타일 색 구분이 중요해서다.

| 용도 | 값 |
| --- | --- |
| 앱 배경 | `#0b0c0f` (`app/globals.css`의 `body`) |
| 패널 — 헤더 바, 트랙 헤더 열 | `#141519` |
| 패널 경계 | `border-white/10` |
| 행 구분선 | `rgb(255 255 255 / 0.07)` |
| 마디선 / 박선 | `white/0.11` / `white/0.035` |
| 본문 텍스트 | `text-zinc-200` · 보조 `text-zinc-400` · 흐림 `text-zinc-500` |
| 플레이헤드 | `bg-red-500` |

악기 색은 클립 타일과 트랙 헤더 점이 같은 계열을 쓴다(`components/studio/instruments.ts`): 피아노 `indigo`, 기타 `emerald`, 베이스 `amber`, 드럼 `rose`. 타일은 `bg-{색}-500/25` + `border-{색}-400/60`.

### 레이아웃

- 앱 셸은 `h-dvh`로 화면을 꽉 채우고 바깥(`body`)은 스크롤하지 않는다. **세로 스크롤 소유자는 `body-scroll` 래퍼 하나**이고, 그 안의 헤더 열과 타임라인은 같은 행에서 함께 늘어난다(`body-columns`, `flex min-h-full`). 타임라인(`timeline`)은 `overflow-x-auto overflow-y-hidden`이라 가로만 스크롤한다 — 세로 스크롤러를 중첩하면 헤더 열과 어긋난다. 가운데 정렬된 `max-w-*` 칼럼을 두지 않는다 — DAW는 화면을 다 쓴다.
- 스테이지에 `min-h-full`과, 마디 컨트롤 폭을 뺀 `minWidth`(`calc(100% - BARS_CONTROL_WIDTH)`)를 준다. 곡이 뷰포트보다 짧아도 격자가 화면을 채우고 마디 ±버튼이 화면 안에 남는다.
- **행 구분선은 `border`가 아니라 `boxShadow`(inset)로 그린다.** border는 박스 높이를 1px 먹어서, 드럼 라인처럼 안쪽 행 높이의 합이 컨테이너 높이와 같아야 하는 경우 헤더 열과 스테이지가 아래로 갈수록 어긋난다. 상수는 `components/studio/layout.ts`의 `ROW_DIVIDER`.
- 트랙 헤더 열과 스테이지는 같은 높이 상수(`components/studio/layout.ts`)를 쓴다. 스테이지 맨 위 눈금자 높이만큼 헤더 열에도 빈 칸을 둔다.
- 스크롤 영역에는 `.timeline-scroll` 클래스를 붙인다(`app/globals.css`). 기본 스크롤바는 어두운 스테이지 위에서 혼자 튄다. **스크롤바를 직접 만들지 않는다** — 휠·트랙패드·키보드·접근성을 전부 다시 만들어야 한다.

## 피아노롤 / 타임라인

노트가 수천 개까지 갈 수 있는 화면이다. 일반 폼 UI와 규칙이 다르다.

- **플레이헤드는 노트와 분리된 레이어**로 그린다. 플레이헤드가 움직일 때 노트 컴포넌트가 리렌더되면 안 된다. `transform: translateX()`만 바꾸고, 값은 `requestAnimationFrame`에서 ref로 직접 쓴다 — `useState`를 거치지 않는다.
- **노트는 DOM 요소로 그린다**(`components/studio/pianoroll/NoteBlock.tsx` — 음 하나당 래퍼 `div` 안에 본문 `button`과 8px 길이 핸들). 포인터 핸들러는 요소마다 달지 않고 격자 요소 하나가 위임으로 받는다. 노트 수가 늘어 프레임이 떨어지면 canvas로 옮긴다. 화면 밖 노트를 그리지 않는 가상화는 **아직 없다**(수백 음 클립의 렌더 비용은 측정하지 않았다 — `docs/known-gaps.md` 12절).
- **격자 선은 DOM 요소가 아니라 CSS 배경이다.** 마디·박·격자 단위 세로선은 `geometry.ts`의 `gridBackground(unit, ticksPerBeat, beatsPerBar)`가 만드는 `linear-gradient` 레이어이고 행 구분선은 `ROW_LINES_BACKGROUND`다. 격자 선마다 `div`를 만들지 않는다(마디 수·격자 단위에 따라 요소가 불어난다). 선 알파는 팔레트의 마디선/박선 값에 맞춘다(`BAR_LINE`·`BEAT_LINE`·`UNIT_LINE`).
- 그리드 계산은 음악적 시간 기준이다. 픽셀 좌표는 렌더 직전에 `pixelsPerBeat × zoom`으로 환산한다. 노트 데이터에 픽셀 값을 저장하지 않는다.
- 줌·스크롤 상태는 React 상태로 둬도 된다(사용자 조작 빈도라서). 단 스크롤 중 매 이벤트마다 전체 리렌더가 나지 않는지 확인한다.

## 인터랙션

- 드래그·리사이즈는 `pointerdown` → `pointermove` → `pointerup` 흐름으로 처리하고, `setPointerCapture`로 요소 밖으로 나가도 추적이 끊기지 않게 한다. **캡처는 `pointerdown`에서 잡는다. 드래그 임계값을 넘길 때까지 기다리지 않는다** — 마우스는 암묵적 캡처가 없어서, 임계값 뒤에 잡으면 8px 핸들이나 클립 가장자리에서 빠르게 끌 때 포인터가 이미 요소 밖이라 `move`·`up`을 못 받아 드래그가 시작조차 못 한다. 캡처 실패(`setPointerCapture`가 던짐)면 제스처를 만들지 않는다. 클릭과 드래그는 놓을 때 정한다(5px 이내면 클릭).
- 드래그 중에는 미리보기만 갱신하고, 실제 곡 데이터 커밋은 `pointerup`에서 한 번만 한다. 드래그 매 프레임마다 `setState`로 곡 전체를 갈아치우지 않는다.
- 키보드 단축키(스페이스=재생/정지 등)는 입력 필드에 포커스가 있을 때 가로채면 안 된다. 핸들러에서 `event.target`을 확인한다. 이미 `defaultPrevented`인 이벤트는 무시한다.
- **`Esc` 한 번은 한 겹만 닫는다**: 진행 중인 드래그 → 열린 팝오버 → 선택 순서다. 드래그·팝오버는 `document`의 캡처 단계 리스너에서 처리하고 `preventDefault()`로 표시하며, 선택 해제(버블 단계, `useShortcuts`)는 `defaultPrevented`면 건너뛴다. 피아노롤 모달 안에서는 진행 중인 제스처 → 음 선택 해제 → 모달 닫기 순서다(아래 모달 절).
- **소리를 내는 모든 진입점은 사용자 제스처 안에 있어야 한다.** 재생 버튼, 건반 클릭, 노트 미리듣기 핸들러에서 `AudioContext.resume()`이 보장되는지 확인한다 (`.claude/rules/audio-engine.md` 참고).
- 포인터로 시작한 조작에는 **취소 경로**를 둔다. `pointercancel`·`lostpointercapture`(놓기 없이)·`Esc`·편집 불가로 바뀜·언마운트에서 미리보기를 되돌리고 상태를 비운다. 없으면 터치 패닝이나 요소 언마운트로 `pointerup`이 안 와서 DOM에 쓴 미리보기가 남고, React가 소유한 속성이면 다시 쓰이지 않아 영구히 굳는다. 포인터로 끄는 요소에는 `touch-action: none`을 준다.
- `pointerdown`은 우클릭에도 온다. 편집을 시작하는 핸들러는 `event.button !== 0`이면 일찍 반환한다.
- **DOM에 직접 쓴 미리보기를 `""`로 지우지 않는다.** React가 그 속성을 소유하고 있으면 React의 스타일 기록과 어긋나 다음 렌더에서 같다고 판단해 다시 쓰지 않는다. 시작 시점의 문자열을 저장해 그대로 되돌린다.

피아노롤 모달(`components/studio/pianoroll/`, 화음 악기만). 규칙(스냅·겹침·경계·클램프)은 `lib/score/notes.ts`가 갖고 UI는 좌표 변환·5px 임계값·미리보기·선택만 한다. 이동·길이·세기는 놓을 때 한 번 커밋한다(한 제스처 = 히스토리 한 칸):

| 제스처 | 결과 |
| --- | --- |
| 격자 빈 곳 클릭 | 누른 칸(격자 단위로 내림)·행에 음 추가(기본 한 칸 길이, 세기 0.8)하고 그 음을 선택. 같은 음높이 음이 시작을 품거나 범위 밖이면 아무 일 없다 |
| 음 클릭 | 그 음만 선택. `Shift`+클릭은 선택 토글 |
| 빈 곳 드래그(5px부터) | 박스 선택. 화면에 그린 박스와 겹치는 음을 고른다(`Shift`면 기존 선택에 더한다) |
| 음 본문 드래그 | 이동. 선택 전체를 한 덩어리로 옮긴다(선택에 없던 음을 끌면 그 음만 선택·이동). 칸 단위 시간 스냅, 행 단위 음높이. 하나라도 클립 경계·음높이 범위·같은 음높이 겹침에 걸리면 **전체 거부**(미리보기는 마지막 유효 위치 유지) |
| 음 오른쪽 8px 핸들 드래그 | 길이 조절. 선택 전체에 같은 변화량을 주되 덩어리째 클램프, 음마다 최소 한 칸 |
| 세기 막대 세로 드래그(5px부터) | 세기. 놓을 때 값 하나를 선택 전체(누른 음이 선택에 있으면)나 그 음에 적용, `[0.05, 1]`. 클릭만으로는 바뀌지 않는다 |
| 세기 막대 포커스 + `↑`/`↓` | 세기 ±5% |
| `←`/`→` · `↑`/`↓` · `Shift`+`↑`/`↓` | 선택한 음을 시간 ±격자 단위 · 반음 ±1 · 옥타브 ±12 이동(거부되면 아무 일 없다) |
| `Alt`+`←`/`→` | 선택한 음 길이 ±격자 단위 |
| `Delete` / `Backspace` | 선택한 음 삭제(삭제 뒤 선택 비움) |
| `Ctrl`/`Cmd`+`A` | 클립의 음 전체 선택 |
| `Esc` | 한 번에 한 겹: 진행 중인 제스처 취소 → 음 선택 해제 → 모달 닫기 |
| `Space` · `Ctrl`/`Cmd`+`Z` | 모달 안에서도 곡 전체 재생/정지, 되돌리기. 재생 중·재생 대기 중에도 모달은 열려 있고 편집만 막힌다 |

키보드 음 편집(`useNoteKeys`)은 포커스가 격자 영역 안이거나 어디에도 없을 때만 처리하고, 입력 요소와 `role="slider"`(세기 막대 — 자기 `↑/↓`를 가진다) 위에서는 건드리지 않는다. 선택이 없으면 이동·길이·삭제는 처리하지 않는다(`Ctrl/Cmd+A`만 예외). `defaultPrevented`·`isComposing`·진행 중 제스처·편집 불가면 건너뛰고, 처리했을 때만 `preventDefault`한다.

편집은 정지 중에만 동작한다. `useStudio().editable`은 `!playing && !pending`이다(`pending` = `play()`가 컨텍스트 재개·샘플 준비를 기다리는 중). 재생 중에는 편집 컨트롤이 비활성(`aria-disabled` 또는 `disabled`)이 되고 "재생 중에는 편집할 수 없습니다"가 표시된다.

## 모달·포털

피아노롤(`pianoroll/PianoRoll.tsx`)이 첫 모달이다. 새 모달·오버레이도 같은 규칙을 따른다.

- `createPortal(…, document.body)`로 그리고 `fixed inset-0 z-50`, `role="dialog"` + `aria-modal="true"` + `aria-label`을 준다. 서버 렌더에서는 열려 있지 않다(곡과 별개인 UI 지역 상태로 `Studio`가 `roll`을 쥔다).
- **포커스 가두기:** `useFocusTrap(rootRef, { initialFocusRef, returnFocus })`. 열릴 때 지정한 요소로, `Tab`/`Shift+Tab`은 끝에서 반대편 끝으로 돌고(안에 포커스가 없으면 끌어온다), 닫히면 연 요소(문서에서 떨어졌으면 클립 본문 버튼)로 돌려준다. **첫 포커스를 닫기 버튼에 두지 않는다** — 키보드로 연 직후 Space가 포커스된 버튼의 클릭이 되어 모달을 닫는다. 격자 스크롤 영역(`tabIndex=0`)에 준다. 뒤쪽 화면에 `inert`·`aria-hidden`은 걸지 않는다(알려진 한계, `docs/known-gaps.md` 12절).
- **열림 카운터:** 모달은 마운트된 동안 `useModalOpenCount(true)`(`components/studio/modal.ts`)로 센다. effect에서 올리고 정리에서 내려 StrictMode 모의 언마운트에도 균형이 맞는다. 전역 단축키(`useShortcuts`)는 `hasOpenModal()`을 **동기적으로** 읽어, 모달이 열린 동안 `Delete`/`Backspace`(클립 삭제)와 `Esc`(선택 해제)를 양보한다. 모달 안의 `Space`(재생/정지)·`Ctrl/Cmd+Z`는 전역 그대로다 — `useShortcuts`는 `aria-modal="true"`인 대화상자를 Space의 네이티브 영역에서 제외한다. 팝오버 카운터(`popover.ts`)와 같은 방식이다.
- **Esc:** 모달은 `document` **캡처 단계**에서 처리하고 `preventDefault()`로 표시한다. 이미 처리된 Esc(`defaultPrevented`)나 진행 중 제스처(`hasActiveGesture()`)가 있으면 건너뛴다. 제스처 훅은 포인터를 누른 순간부터 자기 Esc 리스너와 `beginGesture()`를 걸어 모달이 같은 Esc에 반응하지 않게 한다. 선택이 있으면 선택만 풀고, 없으면 닫는다.
- **재생·편집 불가:** 재생 중·재생 대기 중에도 모달은 열려 있고(헤더에 재생·정지·위치·되돌리기·메시지가 있다) `editable`이 거짓이라 편집만 막힌다. 열린 클립이 사라지거나(되돌리기·삭제) 음 클립이 아니게 되면 `Studio`가 모달을 닫는다.
- 모달이 단 `document` 리스너(키 편집·Esc·Tab 가두기)는 마운트 동안만 걸고 정리한다. 최신 값은 ref로 읽는다(`useShortcuts` 패턴).

## 접근성

- 재생/정지, 트랙 뮤트/솔로 같은 컨트롤은 실제 `<button>`이어야 한다. `<div onClick>`으로 만들지 않는다.
- 피아노롤의 음 본문은 `button`(이름 "C4, 3마디 1박, 길이 1/8")이라 Tab으로 닿고, 선택된 음은 키보드로 옮기고 늘이고 지운다. 세기 막대는 `role="slider"`(`aria-valuemin/max/now`, `↑/↓`). **빈 곳에 음 추가·박스 선택·길이 핸들은 포인터 전용**이다 — 새 제스처를 추가하면 키보드 대안을 함께 두거나 한계를 `docs/known-gaps.md`에 적는다.
- 트랜스포트 컨트롤과 트랙 목록은 탭 순서가 통하게 한다.
- 색만으로 상태를 구분하지 않는다(뮤트된 트랙, 선택된 노트 등).

## 검증

- `pnpm dev`로 실제로 띄워 본다. diff는 화면이 어떻게 보이는지 알려주지 않는다.
- 노트를 많이 배치한 상태에서 스크롤·줌·재생이 부드러운지 본다.
- 좁은 화면과 넓은 화면 양쪽에서 트랙 헤더와 타임라인이 어긋나지 않는지 본다.
