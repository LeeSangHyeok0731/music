# 타일 편집 — 설계

작성일 2026-08-01 · 이전 슬라이스: [읽기 전용 타임라인과 재생](2026-07-31-tile-timeline-playback-design.md)

## 무엇을 만드는가

타임라인에서 곡을 실제로 만들 수 있게 한다. 지금은 하드코딩된 데모 곡을 그리고 재생만 한다 — 타일을 클릭해도 아무 반응이 없다.

```text
빈 칸 클릭        왼쪽의 가장 가까운 타일을 복제해 생성
타일 클릭         선택 + 설정 팝오버
타일 드래그       가로 이동
타일 끝 드래그    길이 조절
우클릭 / Delete   삭제
드럼 칸 클릭      토글 (드래그로 이어 칠하기)
Ctrl+Z            실행취소
```

## 범위

**포함**

- `lib/score/edit.ts` — 곡을 편집하는 순수 함수들
- 음정 라인: 타일 생성·이동·길이 조절·삭제
- 드럼 격자: 칸 토글, 드래그로 이어 칠하기
- 타일 설정 팝오버: 음 추가/삭제, 세기, 길이
- 단일 선택
- `Ctrl+Z` 실행취소

**제외** — 이후 슬라이스로

재생 중 편집, 다시실행(`Ctrl+Shift+Z`), 다중 선택과 범위 선택, 복사/붙여넣기, 라인 추가/삭제, 세로 드래그(다른 라인으로 이동), 줌, 루프, 시크, 저장/불러오기, 음 선택용 건반 위젯, 일렉기타(신스 악기 5종째).

## 확정된 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 재생 중 편집 | **하지 않는다.** 재생 중 타임라인은 읽기 전용 | 스케줄러의 커서는 `tiles[]`의 인덱스다. 곡이 바뀌면 그 인덱스가 가리키던 타일이 달라져 노트가 조용히 누락되거나 중복 예약된다. 이걸 열지 않으면 스케줄러를 한 줄도 건드리지 않는다 |
| 새 타일의 내용 | 클릭 위치 **왼쪽의 가장 가까운 타일**을 복제 | 음정 라인에는 세로 축이 없어 클릭 위치가 음높이를 알려주지 않는다. 복제는 반복 입력이 빠르고, 무엇보다 별도 상태가 필요 없다 — "마지막에 만든 타일"을 기억하면 실행취소 시 그 기억도 되돌려야 한다 |
| 설정 패널 | 타일 옆 팝오버 | 손과 눈이 같은 자리에 머문다. 평소에는 화면을 차지하지 않는다 |
| 편집 로직의 위치 | `lib/score/edit.ts`의 순수 함수 | 브라우저 없이 테스트된다. 정렬 불변식을 지킬 곳이 한 군데로 모인다 |
| 실행취소 | `Ctrl+Z`만. 다시실행 없음 | 곡이 이미 불변 상태라 이전 것을 배열에 쌓기만 하면 된다. 드래그로 옮긴 타일은 되돌릴 방법이 없어 없으면 아프다 |
| 스냅 | 16분음표(120틱) 고정 | 드럼 격자가 이미 1/16이다. 두 라인 종류가 같은 격자를 쓴다 |
| 선택 | 단일만 | 다중 선택은 삭제·이동의 의미를 다시 정해야 해서 별도 슬라이스가 맞다 |

`useReducer`나 별도 스토어 라이브러리는 채택하지 않았다. 액션 타입이 결국 편집 함수 목록과 1:1이라 얻는 게 적고, 이 저장소에는 리듀서가 하나도 없어 새 패턴을 들이게 된다. 라이브러리 추가는 `.claude/rules/ui-conventions.md`가 먼저 묻도록 요구한다.

## 편집 레이어

`lib/score/edit.ts`가 새로 생긴다. 전부 `Song → Song` 순수 함수이며 Web Audio도 React도 import하지 않는다.

```ts
addTile(song, lineId, at: number): Song
moveTile(song, lineId, tileId, startTicks: number): Song
resizeTile(song, lineId, tileId, lengthTicks: number): Song
removeTile(song, lineId, tileId): Song
setTileNotes(song, lineId, tileId, notes: number[]): Song
setTileVelocity(song, lineId, tileId, velocity: number): Song
toggleDrumCell(song, lineId, startTicks: number, piece: number): Song
```

**모든 함수가 반환 전에 해당 라인의 `tiles`를 `start` 오름차순으로 정렬한다.** 지금 이 불변식은 fixture 로드 시점에만 보장된다. 편집이 들어오면 매 편집마다 지켜야 한다 — 깨지면 스케줄러가 커서로 전진하다 노트를 조용히 누락시키고, 귀로도 잡기 어렵다. 한곳에 몰아두면 테스트도 한곳에서 끝난다.

**원본 `Song`을 제자리에서 변형하지 않는다.** 바뀐 라인만 새 객체로 만들고 나머지는 참조를 그대로 넘긴다. React Compiler가 켜져 있지 않으므로 변형은 관찰되지 않고, 실행취소가 이전 스냅샷을 들고 있는 것도 이 전제에 기댄다.

### 타일 id

`crypto.randomUUID()`는 순수하지 않다. 곡 안에서 유일하기만 하면 되므로 다음 규칙을 쓴다.

새 타일의 id는 `tile-<n>` 형태다. `n`은 곡 전체를 훑어 `tile-<숫자>` 패턴에 맞는 id만 골라 그중 가장 큰 숫자 + 1이다. 맞는 것이 없으면 0이다. fixture의 id(`piano-0`, `hihat-3-7`)는 이 패턴에 맞지 않으므로 계산에 끼지 않고 충돌하지도 않는다.

### 경계 규칙

- `start >= 0`, `start + length <= song.lengthTicks`. 밖으로 나가는 이동·길이 조절은 경계에서 멈춘다(거부가 아니라 클램프)
- 최소 길이는 1스냅(120틱)
- **겹침은 허용한다.** 이전 슬라이스가 "화음 안의 음마다 길이·세기를 다르게 주려면 같은 시점에 타일을 겹쳐 놓는다"를 탈출구로 정해뒀다. 겹침은 버그가 아니라 기능이다

### 복제 규칙

`addTile`은 음정 라인 전용이다. 드럼 타일은 `toggleDrumCell`로만 만든다.

클릭한 스냅 위치보다 **`start`가 작은 타일 중 가장 큰 것**을 찾아 `notes` / `length` / `velocity`를 복제한다. `start`는 클릭 위치이고 `id`는 새로 발급한다.

**왼쪽에 타일이 없으면 오른쪽은 보지 않고 기본 타일을 쓴다.** 오른쪽까지 찾으면 "왼쪽에서 오른쪽으로 깔아나간다"는 예측이 깨지고, 라인 맨 앞에 찍을 때마다 뒤쪽 내용이 딸려 온다.

### 기본 타일

왼쪽에 복제할 타일이 없을 때 쓴다. 길이 480틱(4분음표), 세기 0.7.

| 악기 | 음 |
| --- | --- |
| piano | `[60, 64, 67]` (C4 3화음) |
| guitar | `[62, 66, 69]` (D4 3화음) |
| bass | `[36]` (C2) |
| drums | 해당 없음 — 드럼은 격자 토글로만 만든다 |

## 상태 소유권

| 상태 | 사는 곳 | 비고 |
| --- | --- | --- |
| 곡 데이터 | `StudioProvider`의 `useState<Song>` | 기존 `useMemo` 상수를 대체 |
| 실행취소 히스토리 | `StudioProvider`의 `useState<Song[]>` | 편집 직전 곡을 push |
| 선택된 타일 | `StudioProvider`의 `useState<TileRef \| null>` | `TileRef = { lineId, tileId }` |
| 드래그 중 미리보기 | **React 상태가 아니다** | 포인터 이벤트 동안 ref + DOM 직접 |
| 재생 상태 | 기존 그대로 | 변경 없음 |

드래그 중 곡 데이터를 건드리지 않는 것이 중요하다. `.claude/rules/ui-conventions.md`가 *"드래그 중에는 미리보기만 갱신하고, 실제 곡 데이터 커밋은 `pointerup`에서 한 번만"* 을 요구한다. 매 프레임 `setSong`을 부르면 곡 전체가 교체되고 실행취소 히스토리에 수십 개가 쌓인다.

히스토리 상한은 50개다. 곡 하나가 수백 타일이라 스냅샷 자체는 싸지만, 무한히 쌓을 이유도 없다.

**실행취소는 선택을 검사한다.** 되돌린 곡에 선택된 타일이 더 이상 없으면(생성을 되돌린 경우) 선택을 해제하고 팝오버를 닫는다. 그러지 않으면 존재하지 않는 타일의 설정 패널이 떠 있게 된다.

### 엔진 반영

`Engine`은 지금 생성자에서 `song`을 붙잡고 놓지 않는다. `setSong(song: Song)`을 추가해 `StudioProvider`가 곡이 바뀔 때마다 넘긴다.

편집이 정지 중에만 일어나므로 다음 `play()`부터 반영되고, **스케줄러는 손대지 않는다.** 라인 추가/삭제가 범위 밖이라 노드 그래프(악기 인스턴스)도 그대로 유효하다.

## 상호작용

### 음정 라인

| 제스처 | 결과 |
| --- | --- |
| 빈 칸 클릭 | 왼쪽의 가장 가까운 타일을 복제해 스냅 위치에 생성. 없으면 기본 타일 |
| 타일 클릭 | 선택 + 팝오버 |
| 타일 본체 드래그 | 가로 이동. 스냅 단위로 |
| 타일 오른쪽 6px 드래그 | 길이 조절. 스냅 단위로 |
| 우클릭 | 삭제 |
| `Delete` / `Backspace` | 선택된 타일 삭제 |
| `Esc` | 팝오버 닫기, 선택 해제 |
| `Ctrl+Z` | 실행취소 |

세로 드래그는 없다. 라인 = 악기이므로 다른 라인으로 옮기는 것은 이동이 아니라 악기 변경이다.

드래그는 `pointerdown` → `pointermove` → `pointerup`으로 처리하고 `setPointerCapture`로 요소 밖에서도 추적을 유지한다. `pointerup`에서만 곡 데이터를 커밋한다.

### 드럼 격자

칸 토글만 한다. 이동도 길이 조절도 팝오버도 없다 — 격자 칸은 시작 시점과 길이가 이미 정해져 있다.

**드래그로 이어 칠하기를 넣는다.** 8비트 하이햇 16마디를 깔려면 클릭이 128번이다. `pointerdown`에서 방향(켜기/끄기)을 정하고 `pointermove` 동안 그 방향만 적용한다 — 지나가며 토글하면 포인터가 왔다갔다할 때 깜빡인다.

### 설정 팝오버

선택된 타일 아래에 뜬다. 화면 아래쪽 타일이면 위로 뒤집는다. 바깥 클릭이나 `Esc`로 닫는다.

```text
음    [C4 ×][E4 ×][G4 ×][+]
세기  ──●────
길이  1/16 · 1/8 · 1/4 · 1/2 · 1마디
```

음 추가는 C1~C7 범위의 드롭다운으로 한다. 건반 위젯이 더 좋지만 범위 밖이다. 음이 하나 남았을 때는 삭제 버튼을 비활성한다 — 음이 없는 타일은 소리도 안 나고 화면에도 안 보인다.

### 재생 중

편집이 비활성이다. 클릭·드래그가 아무 일도 하지 않고 포인터 커서는 기본값이다. 트랜스포트가 이미 "■ 정지"를 보여주므로 모드가 드러나 있어 별도 안내 문구는 넣지 않는다.

키보드 단축키는 입력 필드에 포커스가 있을 때 가로채지 않는다. 핸들러에서 `event.target`을 확인한다.

## 검증

편집 로직이 순수 함수라 대부분이 브라우저 없이 검증된다. 이전 슬라이스에서 만든 오디오 가짜도 필요 없다.

```text
편집 함수마다
  정렬 불변식이 유지되는가 (start 오름차순)
  원본 Song을 변형하지 않는가
  바뀌지 않은 라인은 참조가 그대로인가
  새 타일 id가 곡 안에서 유일한가

경계
  start < 0 이면 0으로 클램프
  곡 끝을 넘으면 끝에서 멈춤
  최소 길이 아래로 줄어들지 않음
  겹침은 허용됨

드럼
  토글이 켜고 끄기 대칭
  같은 칸을 두 번 토글하면 원래 곡과 같음

실행취소
  편집 직전 곡을 정확히 복원
  히스토리가 비면 더 되돌아가지 않음
  상한(50)을 넘으면 오래된 것부터 버림
  생성을 되돌리면 그 타일의 선택이 풀림

복제
  왼쪽 타일의 notes/length/velocity를 가져오고 start는 클릭 위치
  왼쪽에 없으면 오른쪽을 보지 않고 기본 타일
```

귀와 눈으로 확인할 것:

- 드래그 중 타일 트리가 리렌더되지 않는가 (React DevTools Profiler)
- 편집한 곡을 재생하면 실제로 바뀐 대로 들리는가
- 드럼 이어 칠하기가 포인터를 빠르게 움직여도 칸을 빠뜨리지 않는가

명령은 기존과 같다.

```bash
pnpm lint
pnpm check-types
pnpm build
pnpm test
pnpm dev    # 그리고 실제로 편집하고 들어본다
```

## 알려진 한계

- **재생 중에는 편집할 수 없다.** 들으면서 고치는 것이 작곡에서 아쉬운 부분이라는 걸 알고 내린 결정이다. 열려면 스케줄러의 커서를 인덱스가 아닌 틱 기준으로 바꾸고, 이미 예약된 lookahead 구간을 어떻게 다룰지 정해야 한다
- **다시실행이 없다.** 실행취소를 한 번 더 눌러 되돌릴 수 없다
- **다중 선택이 없다.** 여러 타일을 한꺼번에 옮기거나 지울 수 없다
- **음을 드롭다운으로 고른다.** 건반 위젯보다 느리다
- **타일을 다른 라인으로 옮길 수 없다.** 악기를 바꾸려면 지우고 다시 만들어야 한다

## 구현 후 할 일

`AGENTS.md`의 "현재 상태" 절이 "아직 편집은 없다"고 적고 있다. 이 슬라이스가 편집을 만들므로 사실에 맞게 고친다. `.claude/rules/ui-conventions.md`의 인터랙션 절도 실제 구현된 제스처를 반영해 갱신한다.
