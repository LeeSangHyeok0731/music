# 피아노 편집 화면 — 설계

작성일 2026-08-09 · 이전 슬라이스: [곡 파일 저장·불러오기](2026-08-02-song-file-io-design.md)

## 무엇을 만드는가

피아노 파트만 다루는 전용 화면(`/piano`)을 만든다. 세로가 시간, 가로가 음높이인 피아노롤이고, 아래에 표준 피아노 88건반이 있다. 재생하면 악보가 아래로 내려와 **건반에 닿는 순간 소리가 나고** 그 건반에 불이 들어온다.

```text
┌──────────────────────────────────────────────┐
│ ◀ 타임라인 │ ▶ 재생 │ ♩=120 │ 메트로놈 │ ⭳ ⭱ │
├──────────────────────────────────────────────┤
│                                              │
│        음 블록이 아래로 내려온다               │  ← 위가 나중, 아래가 먼저
│        ▐   ▐▐                                │
│      ▐   ▐                                   │
├──────────────────────────────────────────────┤
│ ▐▐ ▐▐▐ ▐▐ ▐▐▐ … 88건반 (라0 ~ 도8) …          │  ← 닿으면 소리 + 불
└──────────────────────────────────────────────┘
```

### 왜 필요한가

지금 타임라인에서 피아노는 **화음 하나가 블록 하나**다. `notes: [60, 64, 67]`인 타일이 `"도4 미4 솔4"`라는 글자 한 덩어리로 그려지고(`components/timeline/TileLine.tsx`), 라인 높이는 `PITCHED_LINE_HEIGHT = 60`으로 고정이다. **세로축이 음높이를 전혀 표현하지 않는다.** 음을 눈으로 보며 배치하는 것이 구조적으로 불가능하다.

## 범위

**포함**

- `/piano` 라우트와 `components/piano/` 일습
- `StudioProvider`를 `app/layout.tsx`로 이동 (두 화면이 같은 곡·엔진을 공유)
- `lib/score/edit.ts`에 음 단위 편집 함수 추가 (`splitNoteToTile`, `addPianoNote`, `assignLanes`)
- 88건반 음역 상수와 `NotePickerModal`의 음역 확장
- 피아노 전용 JSON 저장·불러오기 (`bandline-piano` 형식)
- 타임라인 음정 라인의 겹침 층 쌓기와 접기/펼치기

**제외** — 이후 슬라이스로

다른 악기의 전용 화면, 줌, 노트 가상화, 페달·다이내믹 기호, MIDI 입력, 코드 인식/자동 화음, 왼손·오른손 파트 분리 저장, 마우스 오른쪽 드래그로 여러 음 선택.

## 확정된 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 데이터 범위 | **같은 `song`의 `line-piano`를 편집한다.** 별도 문서가 아니다 | 진실이 하나다. 피아노에서 찍은 음이 타임라인에 즉시 반영되고, 엔진·스케줄러·실행취소를 그대로 쓴다 |
| 재생 기준선 | **건반 윗면이 "지금"이다.** 별도 플레이헤드 선을 두지 않는다 | 어느 건반을 누를지 눈으로 바로 읽힌다. 블록 아랫변이 닿으면 소리 시작, 윗변이 지나가면 끝 — 블록 높이가 그대로 음 길이다 |
| 시간 방향 | **아래가 먼저, 위가 나중.** 재생 중 악보가 아래로 내려온다 | 위 결정의 필연적 귀결이다. 건반이 아래 있으므로 나중 음이 위에서 내려와야 닿는다 |
| 음역 | **표준 피아노 88건반.** 라0(MIDI 21) ~ 도8(MIDI 108) | 요청 사항. 흰건 52개 |
| 건반 폭 | **흰건 24px 고정 + 가로 스크롤** | 전체 폭 1248px. 넓은 화면은 다 들어오고 좁은 화면만 스크롤한다. 화면 폭에 맞춰 늘리면 좁은 노트북에서 건반이 클릭 불가능할 만큼 좁아진다 |
| 가로 스크롤 동기화 | **건반과 롤을 하나의 가로 스크롤 컨테이너에 넣는다** | `scrollLeft`가 하나뿐이라 어긋날 경로가 없다. 두 개를 만들어 동기화하면 피드백 루프와 드리프트가 생긴다 |
| 데이터 모델 | **`Tile.notes`를 유지한다.** 피아노 화면은 항상 `notes.length === 1`인 타일을 만든다 | 스키마 변경 없음. 기존 파일이 그대로 열린다. 변경이 `lib/score/edit.ts` 순수 함수에 갇혀 테스트 가능한 계층에 머문다 |
| 화음 타일 | **읽을 때 음마다 블록으로 펼친다.** 개별 편집 시 그 음만 새 타일로 분리 | 같은 시각·같은 길이의 음 세 개는 화면상 화음과 구분되지 않는다. 소리도 동일하다 |
| 피아노 파일의 템포 | **담되 적용하지 않는다.** 현재 곡과 다르면 경고 한 줄 | 틱은 템포 독립이라 음악 내용이 안 바뀐다. 남의 파트를 가져왔다고 곡 템포가 바뀌면 놀랍다. 박자표가 다르면 마디가 안 맞으므로 알려야 한다 |
| 접힘 상태 | **곡 데이터가 아니라 보기 설정.** `Timeline`의 지역 상태 | 저장 파일에 들어가면 안 된다. 다른 사람이 연 파일에서 내 접힘 상태가 재현될 이유가 없다 |
| 재생 중 편집 | **잠근다** (기존 규칙 유지) | 스케줄러 커서가 `tiles[]` 인덱스다. 재생 중 곡이 바뀌면 노트가 조용히 누락된다 |

## 라우팅과 상태 공유

```text
app/layout.tsx          StudioProvider를 여기로 올린다        ← 변경
app/page.tsx            타임라인 (Provider만 빠짐)            ← 변경
app/piano/page.tsx      피아노 편집 화면                      ← 신규
```

Next 문서(`node_modules/next/dist/docs/01-app/01-getting-started/03-layouts-and-pages.md`)가 명시한다:

> On navigation, layouts preserve state, remain interactive, and do not rerender.

`StudioProvider`가 루트 레이아웃에 있으면 `<Link href="/piano">`로 오가도 **곡·실행취소 스택·`Engine` 인스턴스가 유지된다.** 새 `AudioContext`가 생기지 않는다. 이 성질이 "두 화면이 같은 곡을 공유한다"를 성립시킨다.

`app/layout.tsx`는 서버 컴포넌트로 남고 `metadata`도 그대로다. `"use client"`인 `StudioProvider`가 `children`을 감싸도 children은 서버에서 렌더된 채 넘어간다.

### DOM 구조

```text
<div className="overflow-x-auto overflow-y-hidden">   ← scrollLeft가 여기 하나뿐
  <div style={{ width: KEYBOARD_WIDTH }}>             ← 1248px
    <div className="flex-1 overflow-y-auto">  롤       ← 세로 스크롤은 여기서만
    <div style={{ height: KEYBOARD_HEIGHT }}> 건반     ← 아래 고정
  </div>
</div>
```

세로 스크롤이 롤 안쪽에만 있으므로 건반은 항상 아래에 남는다. 가로는 바깥 컨테이너가 소유하므로 건반과 롤이 함께 움직인다.

## 데이터 모델 — 타일이 쪼개지는 이유

현재 `Tile`은 화음 하나를 담는다:

```ts
type Tile = {
  start: number;    // 시작 틱
  length: number;   // 길이 틱
  velocity: number;
  notes: number[];  // 화음이 여기 다 들어간다 — start·length·velocity를 공유
};
```

그래서 **"도4를 1박 길이로, 미4를 같은 시각에 2박 길이로"를 하나의 타일로 표현할 수 없다.** 피아노 화면에서는 당연히 되어야 하는 조작이다.

해결은 편집이 일어날 때 그 음만 떼어내는 것이다:

```text
편집 전   { start: 0, length: 480, notes: [60, 64, 67] }

미4(64)를 옮기고 늘리면

편집 후   { start: 0,   length: 480, notes: [60, 67] }   ← 미4가 빠짐
          { start: 240, length: 960, notes: [64] }        ← 미4가 새 타일로
```

소리는 완전히 동일하다. **타임라인의 블록 개수만 1개에서 2개로 늘어난다.** 이것이 이 결정의 유일한 가시적 대가이고, 아래 "타임라인 층 쌓기"가 그 결과를 감당한다.

### 새 순수 함수 — `lib/score/edit.ts`

```ts
/** 타일에서 음 하나를 떼어 새 타일로 만든다. 남은 음이 없으면 원본 타일을 지운다. */
splitNoteToTile(song, lineId, tileId, note): { song: Song; newTileId: string }

/** 항상 notes.length === 1인 타일을 만든다. 피아노 화면의 배치용. */
addPianoNote(song, lineId, startTicks, note): Song

/** 시간상 겹치는 타일을 층으로 나눈다. 타임라인과 피아노 화면이 함께 쓴다. */
assignLanes(tiles: Tile[]): Map<string, number>
```

`assignLanes`는 시작 시각 순으로 훑으며 "이미 끝난 층" 중 가장 낮은 번호에 배치하는 그리디 방식이다. 반환값의 최댓값 + 1이 필요한 층 수다.

세 함수 모두 **순수 함수**이고 `lib/score/`에 산다. 이 계층은 테스트가 실제로 존재하는 유일한 곳이다(`docs/known-gaps.md` 참고).

`splitNoteToTile`이 지켜야 할 불변식:

- 결과 타일 배열은 `start` 오름차순을 유지한다 (`Line.tiles`의 불변식)
- 새 id는 `nextTileId(song)`로 받는다 — 곡 전체에서 `tile-<숫자>` 최댓값 + 1이라 충돌하지 않는다
- 마지막 음을 떼어내면 원본 타일은 `notes: []`로 남기지 않고 **삭제한다.** 빈 `notes`는 스키마가 거부하고(`.min(1)`), 화면에도 소리에도 나타나지 않는 유령이 된다

## 좌표계

`components/piano/layout.ts`에 모은다. 타임라인의 `components/timeline/layout.ts`와 같은 역할이다.

```ts
export const PIANO_MIN_MIDI = 21;   // 라0
export const PIANO_MAX_MIDI = 108;  // 도8
export const WHITE_KEY_WIDTH = 24;
export const BLACK_KEY_WIDTH = 15;  // 흰건의 약 0.62
export const KEYBOARD_WIDTH = 52 * WHITE_KEY_WIDTH;  // 1248
export const KEYBOARD_HEIGHT = 84;

/** 마디당 세로 픽셀. 4/4에서 1박 60px, 1/16(=MIN_TILE_LENGTH) 15px. */
export const PX_PER_BAR = 240;
```

**가로 (MIDI → x)** — 흰건은 흰건 인덱스 × 24. 검은건은 앞 흰건의 오른쪽 경계에 중심을 두고 폭 15px. 롤의 열 위치가 건반과 1:1로 맞아야 하므로 두 컴포넌트가 같은 함수를 쓴다.

**세로 (틱 → y)** — `tickToPy(tick, perBar) = (tick / perBar) * PX_PER_BAR`. 타임라인의 `tickToPx`와 같은 꼴이고 상수만 다르다. 블록의 아랫변이 `start`, 높이가 `length`다.

**아래가 0이다.** 롤 안에서 블록은 `bottom` 기준으로 배치한다. `top` 기준으로 하면 곡 길이가 바뀔 때마다 모든 블록의 좌표를 다시 계산해야 한다.

### 음역 확장의 파급

`lib/score/notes.ts`의 `MIN_OCTAVE = 1` / `MAX_OCTAVE = 7`은 도1(24) ~ 시7(107)이라 88건반보다 좁다. 피아노 화면이 라0(21)이나 도8(108)에 음을 만들면, 그 타일을 타임라인에서 클릭했을 때 `NotePickerModal`이 표시할 수 없는 음을 받는다.

**`NotePickerModal`을 88건반 범위로 넓힌다.** 옥타브 0과 8을 추가하되 각각 라0부터 / 도8까지로 잘라낸다. 이것이 이 슬라이스에서 **새 화면 바깥을 건드리는 가장 위험한 지점**이다 — 기존 화면의 동작을 바꾸는 유일한 곳이고, `components/`라 자동 테스트가 없다.

스키마는 이미 MIDI 0~127을 허용하므로 파일 형식은 영향받지 않는다.

## 피아노 전용 JSON

기존 `bandline-song`과 같은 봉투 패턴을 따른다.

```json
{
  "format": "bandline-piano",
  "version": 1,
  "piano": {
    "tempo": 120,
    "timeSignature": [4, 4],
    "lengthTicks": 30720,
    "tiles": [
      { "id": "tile-0", "start": 0, "length": 480, "velocity": 0.7, "notes": [60] }
    ]
  }
}
```

`schema.ts`의 `TileSchema`를 export해 재사용한다. 새 파서 `parsePianoPart(text)`도 기존 규약을 지킨다 — **예외를 던지지 않고** `{ ok: true, part } | { ok: false, reason }`을 돌려준다. 호출부가 `try/catch` 없이 `reason`을 그대로 화면에 띄울 수 있어야 한다.

### 불러오기 동작

1. `line-piano`의 `tiles`를 **통째로 교체한다.** 병합하지 않는다 — 어떻게 합칠지에 정답이 없고, 사용자가 원하면 두 파일을 손으로 합칠 수 있다
2. `part.lengthTicks`가 현재 곡보다 길면 `song.lengthTicks`를 **늘린다. 짧아도 줄이지 않는다** — 다른 라인의 노트가 잘려나가면 안 된다
3. `tempo` / `timeSignature`가 현재 곡과 다르면 **경고 한 줄**을 띄우되 적용하지 않는다. 기존 `setError` 통로를 쓴다
4. `commitWith`로 커밋해 **실행취소 스택에 쌓는다** — `Ctrl+Z`로 되돌아간다
5. 타일 id는 그대로 둔다. 스키마가 라인 안 유일성만 요구하고, `nextTileId`가 곡 전체를 훑으므로 이후 발급도 충돌하지 않는다

`song.tempo`는 바뀌지 않으므로 **`setTempo`를 부를 필요가 없다.** (곡을 통째로 바꾸는 경로에서 이걸 빠뜨려 화면과 재생 속도가 갈라진 전례가 있다 — `AGENTS.md` 참고. 이 경로는 템포를 건드리지 않는다는 것이 결정이므로 해당하지 않는다.)

## 상태 소유권과 재생

이 슬라이스에서 가장 틀리기 쉬운 부분이다.

**매 프레임 값은 React 상태에 넣지 않는다.** 낙하 위치와 건반 불은 둘 다 매 프레임 바뀐다.

```text
rAF 루프 (components/timeline/Playflag.tsx가 쓰는 패턴, 축만 세로)
  → currentTick() 읽기              ← audioContext.currentTime 기반
  → 롤의 scrollTop을 직접 쓴다       ← useState를 거치지 않는다
  → 현재 틱에 울리는 음 집합 계산
  → 직전 프레임 집합과 diff          ← 바뀐 건반만 classList 토글
```

낙하를 `transform`이 아니라 **`scrollTop`으로 움직인다.** 롤은 정지 중 편집을 위해 네이티브 세로 스크롤을 갖는 컨테이너이고, 같은 요소를 transform으로도 움직이면 두 좌표계가 겹쳐 스크롤 위치와 화면이 어긋난다. `Playflag`가 이미 rAF에서 `scrollLeft`를 직접 쓰는 선례가 있고, 스크롤바를 직접 만들지 않는다는 규칙과도 맞는다.

**diff가 필수다.** 88개 키를 매 프레임 전부 토글하면 재생 중 메인 스레드를 낭비하고, 그것이 곧 오디오 글리치다.

**시각과 청각이 어긋나지 않는 근거는 낙하 위치와 스케줄러가 같은 `틱 → 초` 변환을 쓴다는 것뿐이다.** rAF 타임스탬프나 `Date.now()`를 섞으면 몇 분 뒤 눈과 귀가 갈라진다. 이 오류는 짧게 들어서는 드러나지 않는다.

React 상태로 두는 것: 선택된 음, 팝오버 열림 여부, 접힘 상태, 그리고 곡 데이터.

| 롤 빈 칸 클릭 | 그 건반·그 시각에 음 생성 (길이 `DEFAULT_TILE_LENGTH`) |
| 블록 클릭 | 선택 + 세기·길이 팝오버 |
| 블록 드래그 | 시간(세로) + 음높이(가로) 동시 이동. 시간은 1/16 스냅, 음높이는 반음 |
| 블록 **위쪽** 끝 드래그 | 길이 조절 — 시간이 위로 흐르므로 "나중" 방향이 위다 |
| 우클릭 / `Delete` | 삭제 |
| 건반 클릭 | 그 음 미리듣기 |
| `Esc` | 팝오버 닫기, 선택 해제 |
| `Ctrl+Z` | 실행취소 (타임라인과 공유) |

승계하는 규칙:

- `setPointerCapture`로 요소 밖으로 나가도 추적이 끊기지 않게 한다
- `pointercancel`·`lostpointercapture`에서 미리보기를 되돌린다. DOM에 직접 쓴 미리보기를 `""`로 지우지 않고 **시작 시점 문자열로 되돌린다**
- 포인터로 끄는 요소에 `touch-action: none`
- `event.button !== 0`이면 조기 반환 (`pointerdown`은 우클릭에도 온다)
- 드래그 중엔 미리보기만 갱신하고 커밋은 `pointerup`에서 한 번
- 편집은 정지 중에만 — `useStudio().editable`

**건반 미리듣기는 소리를 내는 새 진입점이다.** 사용자 제스처 안에서 `AudioContext.resume()`이 보장되는 경로여야 한다. 이것이 "눌렀는데 아무 소리도 안 남"의 1순위 원인이다.

## 타임라인 층 쌓기와 접기/펼치기

타일이 쪼개지면 같은 시간대에 타일이 겹친다. 지금 `TileLine`은 모든 타일을 `top: TILE_INSET` 한 줄에 그리므로 **겹친 타일이 서로를 덮는다.**

`assignLanes`로 층을 나눠 아래로 쌓는다. 층이 늘면 라인이 높아지므로, **3층 이상이면** 라인 헤더에서 접었다 펼 수 있게 한다.

- **펼침** — 층마다 한 행. 라인 높이 = 층 수 × 행 높이
- **접힘** — 지금과 똑같이 한 행에 전부 겹쳐 그린다. 새 렌더 로직이 필요 없고 "뭔가 있다"는 보인다

**기본은 펼침이다.** 3층에 도달했다고 자동으로 접지 않는다 — 방금 찍은 음이 사라진 것처럼 보인다. 토글은 3층 이상일 때만 헤더에 나타난다.

### 깨는 불변식

`components/timeline/layout.ts`에 이렇게 적혀 있다:

```ts
/** 라인 높이는 데이터에서 계산하지 않고 kind별 상수로 둔다. */
export function lineHeight(kind: LineKind): number
```

층 수가 데이터에 달렸으므로 이 불변식을 **의도적으로 깬다:**

```ts
export function lineHeight(line: Line, collapsed: boolean): number
```

위험한 변경이다. `ui-conventions.md`가 경고한다 — **트랙 헤더 열과 스테이지는 같은 높이 상수를 써야** 아래로 갈수록 어긋나지 않는다. `LineHeaders`와 `Timeline`이 반드시 이 한 함수를 통과하게 묶는다. 행 구분선은 계속 `border`가 아니라 `ROW_DIVIDER`(inset shadow)로 그린다 — border는 박스 높이를 1px 먹어 층이 쌓일수록 어긋남이 누적된다.

## 구현 순서

각 단계가 끝날 때 실제로 확인 가능한 단위로 자른다.

1. **`lib/score/` 순수 함수 + 테스트** — `assignLanes`, `splitNoteToTile`, `addPianoNote`, 88건반 상수. 화면 없이 검증된다
2. **Provider를 `app/layout.tsx`로 + `/piano` 라우트 + 링크** — 빈 화면이어도 오갈 때 곡이 유지되는지 확인
3. **건반 + 롤 렌더, 정지 상태 편집** — 여기서 화면이 쓸 만해진다. `NotePickerModal` 음역 확장 포함
4. **재생 낙하 + 건반 불** — 소리로 확인하는 단계
5. **피아노 JSON 저장·불러오기**
6. **타임라인 층 쌓기 + 접기/펼치기**

6번은 타임라인 쪽 작업이라 **별도 슬라이스로 떼어도 된다.** 1~5로 피아노 화면은 완결되고, 6번 없이도 타임라인은 지금처럼 동작한다 — 겹친 타일이 서로 가려 보일 뿐이다.

## 테스트

`lib/score/`에 넣는다. 이 계층만 자동 테스트가 의미 있게 동작한다.

| 대상 | 확인할 것 |
| --- | --- |
| `assignLanes` | 안 겹치면 전부 0층. 완전히 겹치면 층이 하나씩 는다. 끝나는 시각과 시작 시각이 같으면 같은 층을 재사용한다 |
| `splitNoteToTile` | 남은 음이 원본에 유지된다. 마지막 음을 떼면 원본이 삭제된다. `start` 정렬이 유지된다. 새 id가 충돌하지 않는다 |
| `addPianoNote` | 항상 `notes.length === 1`. 스냅이 적용된다. 곡 경계를 넘지 않는다 |
| 피아노 파일 | 왕복(직렬화 → 파싱)이 같은 값을 준다. `format`·`version`이 틀리면 거부한다. 손으로 고친 소수점 틱이 복구된다 |

### 테스트하지 않는 것

`components/piano/`와 `state/`. `vitest.config.mts`가 `environment: "node"`이고 `include`가 `lib/**`·`state/**`뿐이며, `@testing-library/react`도 `jsdom`도 설치돼 있지 않다. **이 슬라이스의 대부분이 여기 떨어진다.**

`docs/known-gaps.md`에 기록된 대로 최근 세 슬라이스의 심각한 결함 4건이 전부 이 계층에서 나왔고 전부 최종 리뷰에서야 잡혔다. 검사가 전부 통과해도 이 화면이 동작한다는 근거가 되지 않는다.

## 검증

```bash
pnpm lint
pnpm check-types
pnpm test
pnpm build
```

`pnpm build`는 예외적으로 의미가 있다 — 모듈 스코프에서 `AudioContext`를 만들면 서버 렌더링 중 평가되어 여기서 깨진다. 새 라우트가 생기므로 이 경로가 늘어난다.

### 반드시 들어서 확인할 것

정적 검사가 아무것도 증명하지 못한다.

| 항목 | 확인 방법 |
| --- | --- |
| 시각-청각 동기 | 건반에 닿는 순간과 소리 나는 순간이 맞는가 |
| 장시간 드리프트 | 메트로놈을 켜고 30초 이상 완주. 낙하와 소리가 벌어지지 않는가. **짧은 청취로는 판단할 수 없다** |
| 첫 클릭 미리듣기 | 페이지를 새로 열고 건반을 처음 눌렀을 때 소리가 나는가 (`AudioContext`가 suspended면 조용히 실패한다) |
| 스크롤 중 오디오 | 88건반을 가로로 스크롤하면서 재생할 때 튀지 않는가 |
| 화면 이동 후 재생 | `/` ↔ `/piano`를 오간 뒤에도 곡과 재생이 유지되는가 |
| 좁은 화면 | 노트북 폭에서 건반과 롤의 가로 위치가 어긋나지 않는가 |

## 미루는 것 — `docs/known-gaps.md`에 기록한다

- **노트 가상화를 하지 않는다.** 화면 밖 노트도 전부 DOM으로 그리고 `memo`로만 끊는다. 데모 곡 16마디 규모에서는 문제없지만 노트가 수천 개가 되면 프레임이 떨어진다. `ui-conventions.md`가 요구하는 화면 밖 생략은 그때 넣는다
- **줌이 없다.** 세로 배율(`PX_PER_BAR = 240`)과 건반 폭(24px)이 고정이다
- **다중 선택·복사/붙여넣기가 없다.** 기존 타임라인과 같은 제약이다
