# 피아노롤(하위 프로젝트 2b-1) 설계

날짜: 2026-11-21. 선행: `2026-11-21-arrangement-editor-design.md`(2a, 병합됨, PR #9), 모델·엔진은 `2026-11-20-core-model-sample-engine-design.md`(§3 모델은 v3로 대체됨).

## 1. 목적과 범위

비전공자가 2a에서 코드 진행과 패턴으로 곡 뼈대를 만든 뒤, **멜로디나 세부를 음 단위로 직접 손보는** 화면을 추가한다. 패턴 클립을 음 클립으로 바꿔(굽기) 피아노롤에서 음을 찍고 옮기고 늘이고 지운다. 곡 모델은 바꾸지 않는다(v3 그대로, `notes` 클립 본문은 이미 있다).

| 항목 | 결정 |
| --- | --- |
| 범위 | **화음 악기(피아노·기타·베이스)의 피아노롤.** 드럼 그리드는 2b의 두 번째 단계(별도 설계·계획) |
| 화면 | 클립을 **화면 전체로 확대(모달)**. 닫으면 곡 화면으로 돌아온다 |
| 소리 | 곡 전체 재생만(처음부터, 모달 안 플레이헤드). **음 미리듣기 없음**, 구간 반복 재생 없음 → **엔진은 바뀌지 않는다** |
| 음 클립 만들기 | 패턴 클립 **굽기** + **빈 음 클립** 만들기 둘 다 |
| 편집 동작 | 기본(추가·선택·이동·길이·삭제) + **격자 단위(1/4·1/8·1/16)**, **여러 음 선택(Shift 클릭·드래그 박스)**, **세기(velocity) 편집**, **키보드 이동(화살표)** |
| 이번에 안 하는 것 | 드럼 그리드, 음 미리듣기, 반복 재생, 복사/붙여넣기, 다시실행, 줌, 트랙 추가·삭제, 곡 파일 열기·저장 UI |

비전공자 보조: 클립 구간의 코드를 읽기 전용 띠로 보여 주고, 그 코드의 구성음 행에 옅은 색을 입힌다(어느 음이 어울리는지 보이게).

## 2. 모델과 불변식 (변경 없음, 새 규칙은 편집 함수가 지킨다)

`Note = { start, length, pitch, velocity }`(클립 기준 상대 틱, 정수 틱). 모델·`validateSong`은 그대로다(음 정렬·클립 안·길이 ≥ 1). 아래는 **편집 함수가 추가로 지키는 규칙**이고 `validateSong`의 검사가 아니다(손으로 고친 파일은 이 규칙을 어길 수 있고, 그런 곡도 열린다).

- **같은 음높이끼리는 겹치지 않는다.** 한 클립 안에서 같은 `pitch`인 음의 구간 `[start, start+length)`은 겹치지 않는다(맞닿는 것은 허용). 다른 음높이끼리는 겹쳐도 된다(화음).
- **같은 `(start, pitch)`는 둘 이상 둘 수 없다**(위 규칙에 포함). 음 식별 키는 `NoteKey = "start:pitch"`다. 음에 id를 추가하지 않는다(모델 변경 없음).
- 음은 클립 안에 있어야 한다: `0 ≤ start`, `start + length ≤ clip.length`.
- 기본 세기 `0.8`, 범위 0..1(편집 함수는 `[0.05, 1]`로 클램프해 무음 음을 만들지 않는다).

### 2.1 음높이 UI 범위
악기별 표(UI 한도, 모델은 0..127 허용). 근거는 샘플 팩 존 중심음(piano 36~96, guitar 40~81, bass 25~60)이다.

| 악기 | 범위 | 이름 |
| --- | --- | --- |
| piano | 36..96 | C2~C7 |
| guitar | 40..84 | E2~C6 |
| bass | 28..60 | E1~C4 |

**표시 범위 = 표의 범위 ∪ (클립에 이미 있는 음의 음높이 ± 2)**. 굽거나 손으로 고친 곡의 음이 범위 밖이어도 화면에서 잘리지 않는다. 편집 함수는 새로 놓는 음·이동 결과를 이 **표시 범위**로 제한한다(범위를 벗어나는 이동은 거부).

## 3. 순수 편집 규칙 — `lib/score/notes.ts`

`edit.ts`와 같은 약속: 순수 함수, 새 `Song`을 돌려준다, **바뀌는 게 없으면 같은 참조**, 결과는 항상 `validateSong`을 통과하고 위 §2 규칙을 만족, 입력은 변형하지 않는다. 알 수 없는 트랙·클립 id, `notes` 클립이 아닌 클립은 `Error`.

격자: `GRID_UNITS = { "1/4": 480, "1/8": 240, "1/16": 120 }`(틱). 시작은 격자로 스냅한다(`Math.round`가 아니라 **칸의 시작으로 내림**: 클릭한 칸), 길이 최소·기본은 격자 단위 하나다.

- `bakeClipToNotes(song, trackId, clipId): Song` — `pattern` 클립을 그 시점의 코드 진행으로 `notes` 클립으로 바꾼다(`expand.ts`의 `bakeClip`/`bakeClipInSong` 재사용). `notes` 클립이면 no-op. 한 방향.
- `emptyNotesClip(song, trackId, clipId): Song` — `pattern` 클립을 같은 `id·start·length`의 **빈** `notes` 클립으로 바꾼다. `notes` 클립이면 no-op. (빈 칸 Shift+클릭의 바로 만들기는 `addClip` 후 이 함수를 합친 UI 동작이다.)
- `addNote(song, trackId, clipId, { start, pitch, length?, velocity? }, unit)` — 스냅한 위치에 음을 추가. 같은 음높이의 기존 음과 겹치면 **길이를 다음 음 직전까지 줄이고**, 줄일 수 없으면(시작이 기존 음 안) no-op. 클립 끝·음높이 범위 밖이면 no-op. 결과 선택 키를 돌려준다.
- `moveNotes(song, trackId, clipId, keys, dStart, dPitch, unit)` — 선택된 음들을 **한 덩어리**로 이동. `dStart`는 격자 단위로 스냅. 클립 경계·음높이 범위를 넘거나, 결과가 같은 음높이의 다른 음(선택되지 않은 것 포함, 선택된 것끼리 포함)과 겹치면 **전체 거부(no-op)**. 이동 후 `notes`는 start 오름차순(안정 정렬)을 유지한다. 새 선택 키를 돌려준다.
- `resizeNotes(song, trackId, clipId, keys, dLength, unit)` — 선택된 음들에 같은 변화량을 주되, 전체가 만족하는 최대 범위로 **덩어리째 클램프**: 최소 길이 격자 단위 하나, 다음 같은 음높이 음 직전, 클립 끝. 결과가 같으면 no-op.
- `removeNotes(song, trackId, clipId, keys)` — 키에 해당하는 음 삭제. 없는 키는 무시, 지울 게 없으면 no-op.
- `setVelocities(song, trackId, clipId, keys, velocity)` — 선택된 음의 세기를 같은 값으로. 클램프 `[0.05, 1]`, 같으면 no-op.
- `selectNotesInBox(song, trackId, clipId, box)` — 박스(틱 구간·음높이 구간)와 겹치는 음의 키 목록(UI의 박스 선택용 순수 도우미).
- 모든 선택 키 입력은 클립에 실제로 있는 음으로 걸러서 쓴다(낡은 키는 무시).

이동·길이 함수는 결과 `{ song, keys }`를 돌려주는 **계획 함수**(`planMoveNotes` 등)와 곡만 돌려주는 편집 함수로 나눠, UI가 미리보기와 선택 갱신에 같은 계산을 쓴다(2a의 `planAddClip`과 같은 방식).

## 4. 상태 (`state/StudioProvider`)

- 곡·되돌리기·자동 저장·재생 상태 기계는 그대로. `StudioApi.edit`에 `notes` 묶음을 추가한다: 위 편집 함수들(첫 인자 `song` 제외)을 **기존 `applyEdit` 경로**로 감싼다(`editable`일 때만 동작, 같은 참조면 기록·저장 안 함, 던지면 메시지 + 곡 그대로, `editable` 아닐 때 무시).
- **굽기 안내:** `bakeClipToNotes`가 곡을 바꾸면 메시지 줄에 "음으로 바꿨습니다 — 코드 진행을 바꿔도 이 클립은 따라가지 않습니다. 되돌리기로 복구할 수 있습니다"를 띄운다(마디 축소 안내와 같은 방식, Provider가 소유).
- 모달 열림(`{trackId, clipId} | null`)과 음 선택(`NoteKey[]`)은 **UI 지역 상태**(`Studio` 쪽). 되돌리기·재생 시작 등으로 클립이 사라지거나 `pattern` 클립으로 돌아가면 모달을 닫고, 선택된 키가 없어지면 파생 값으로 걸러 낸다.
- 엔진은 바뀌지 않는다: 음 클립은 이미 `expandSong`을 거쳐 재생된다. 편집은 정지 중에만(재생 중·재생 대기 중 차단, 2a와 같음), 모달은 열린 채 플레이헤드만 움직인다.

## 5. 화면 (`components/studio/pianoroll/`)

**진입/종료**
- 패턴 클립 팝오버에 버튼 두 개: **음으로 바꾸기**(굽기), **빈 음 클립으로**. 빈 트랙 칸 **Shift+클릭**은 빈 음 클립을 바로 만든다.
- 음 클립은 클릭하면 선택, 클립 안의 **편집 버튼**(`aria-label="음 편집"`)이나 **더블클릭/Enter**로 모달이 열린다. 닫기: `← 돌아가기` 버튼, Esc.

**모달** (`role="dialog" aria-modal="true"`, 포털, 화면 전체, 포커스 가두기, 닫으면 연 요소로 포커스 복귀)
- **위:** 클립 제목(트랙 이름·마디 범위), 격자 단위 선택(1/4·1/8·1/16, 라디오), 재생/정지·위치, 되돌리기, 메시지 줄. 재생은 곡 처음부터 전체이고 플레이헤드는 이 클립 구간에서만 보인다.
- **가운데:** 왼쪽 건반 열(음 이름 C4 등, 검은 건반 구분), 오른쪽 격자(가로 = 클립 길이, 세로 = 표시 범위). 격자 선(마디·박·선택한 격자 단위)은 **CSS 배경**으로 그리고 DOM 요소는 음뿐이다. 격자 위에 **코드 띠**(읽기 전용)와 코드 구성음 행 색칠. 가로·세로 스크롤은 격자 영역이 소유한다(바깥 스크롤 없음, `timeline-scroll`). 처음 열 때 음이 있으면 음 범위 중앙으로, 없으면 C4 근처로 세로 스크롤.
- **아래:** 세기 레인(음마다 막대, 높이 = 세기).
- 좌표 변환·격자 스냅·음높이↔y 변환은 `pianoroll/geometry.ts`의 순수 함수(2a의 `geometry.ts`와 같은 규칙: NaN/Infinity·`-0` 정리).

**조작** (2a의 제스처 규칙을 그대로: `pointerdown`에서 캡처, 캡처 실패면 제스처 안 만듦, 취소 경로(pointercancel·lostpointercapture·Esc·편집 불가·언마운트·대상 소멸), 미리보기는 순수 계획 함수로 원본 스냅샷에서 계산, 놓을 때 한 번 커밋, 마우스는 `buttons` 가드, 5px 임계, 클릭 삼키기(`detail > 0`))
- 빈 곳 클릭 → 그 칸의 시작·행에 기본 길이(격자 단위)·세기 0.8의 음을 추가하고 선택.
- 음 클릭 → 선택, Shift+클릭 → 선택에 추가/제거.
- 음 본문 드래그 → 선택된 음 전체 이동(시간·음높이, `planMoveNotes` 미리보기, 거부면 마지막 유효 위치 유지).
- 음 오른쪽 가장자리 8px 핸들 드래그 → 선택 전체 길이 조절(`planResizeNotes`).
- 빈 곳 5px 이상 드래그 → 박스 선택(Shift는 추가). 박스는 미리보기이고 놓을 때 선택이 확정된다.
- 세기 막대 세로 드래그 → 그 음 세기(선택된 음이면 선택 전체를 같은 값으로).
- 키보드(모달 안): `←/→` 격자 단위 이동, `↑/↓` 반음, `Shift+↑/↓` 옥타브, `Alt+←/→` 길이 ± 격자 단위, `Delete/Backspace` 삭제, `Ctrl/Cmd+A` 전체 선택. 음은 실제 `<button>`(Tab 순서 = 시간, 같으면 음높이)이고 `aria-pressed`(선택)와 "C4, 3마디 1박, 길이 1/8" 같은 이름을 가진다.
- **Esc는 한 번에 한 겹**: 진행 중 드래그 → (박스/키 선택) 선택 해제 → 모달 닫기. 드래그 훅은 캡처 단계 + `preventDefault`(2a와 같은 메커니즘).
- **전역 단축키 범위:** 모달이 열려 있는 동안 `useShortcuts`의 `Delete`(클립 삭제)와 Esc 선택 해제는 꺼진다(음 편집이 처리). Space·Ctrl+Z는 그대로. 모달 열림은 팝오버 카운터처럼 모듈 수준 표시(`hasOpenModal()`)로 읽고 정리 경로를 보장한다.
- 편집 불가(`!editable`)면 모든 조작을 무시하고 `aria-disabled`, 열린 드래그는 취소.

## 6. 테스트 전략

2a에서 가장 값졌던 점(순수 로직을 `lib/`에, 실제 Provider로 상태 단언, 변이 검증)을 이어간다.

- `lib/score/notes.ts`: 경계·no-op(같은 참조)·거부 표, **무작위 편집 속성 테스트**(시드 고정, 모든 연산 혼합, 항상 `validateSong === []`, §2 규칙 유지, 입력 불변), 정렬이 안 된 로드된 곡 한 패스. 변이 검증(겹침 검사 제거·덩어리 이동을 개별 이동으로 바꿈·스냅 내림→반올림 등).
- 순수 도우미(좌표·박스 선택·계획 함수)는 컴포넌트와 분리해 단위 테스트.
- 컴포넌트: 실제 `StudioProvider`+가짜 deps로 곡 상태를 단언. 추가·선택·Shift 선택·박스·이동·길이·세기·키보드·삭제, 모달 포커스 가두기·복귀, Esc 단계, 재생 중 편집 차단, 전역 단축키 충돌, 제스처 취소 경로, **캡처가 `pointerdown`에서 잡히는지·이벤트가 다른 요소로 갈 때도 되는지**(2a 테스트 도우미의 재라우팅 사용), 모듈 카운터 누수 없음(afterEach 단언).
- 통합: 패턴 클립 굽기 → 음 편집 → 재생(가짜 엔진이 받은 곡의 `expandSong` 이벤트에 새 음이 나온다) → 되돌리기 → 새로고침 복원.
- **실제 브라우저 점검**(구현 끝에 Chrome으로 같은 흐름 조작, 2a에서 jsdom이 못 본 결함을 잡았다)과 **듣기 확인은 사람 몫**(코드 변경 없이 음을 찍은 소리, 굽기 직후 원래 패턴과 같은 소리인지).

## 7. 구현 순서 (계획의 Task 단위)

1. 순수 규칙 `lib/score/notes.ts`(+ 악기별 범위 표, 굽기·빈 음 클립, 속성 테스트). **상위 모델.**
2. Provider 연결(`edit.notes.*`, 굽기 안내, 모달 열림 표시·전역 단축키 범위) — 테스트.
3. 피아노롤 좌표·격자 순수 함수와 모달 뼈대(진입 버튼·열기/닫기·포커스·건반 열·격자·코드 띠·플레이헤드 일반화).
4. 음 상호작용(추가·선택·Shift·박스·이동·길이). **상위 모델.**
5. 세기 레인과 키보드 이동.
6. 통합 테스트·문서·브라우저 점검.

각 Task는 구현 → 리뷰 → 수정 → 재리뷰, 마지막에 전체 브랜치 리뷰(상위 모델).

## 8. 위험과 결정 기록

- **여러 음 이동 전체 거부**가 답답할 수 있다(막힌 이유가 안 보임). 규칙을 `planMoveNotes` 한 곳에 두어 후속에서 클램프 방식으로 바꿀 수 있게 한다.
- 음 식별을 `(start, pitch)` 키로 하므로 **같은 `(start, pitch)` 중복이 있는 로드된 곡**은 편집 함수가 첫 음만 다룬다(손으로 고친 파일 한정, 열리는 것은 보장).
- 모달은 포커스를 가두므로 **전역 단축키·팝오버 카운터와의 상호작용**이 2a에서 반복해서 결함이 나온 영역이다 → 컴포넌트 테스트에 교차 시나리오를 넣고 실제 브라우저 점검 대상으로 명시한다.
- 굽기는 한 방향이다(코드 진행에 더는 안 따라간다). 안내와 되돌리기로 보완하고, "음 클립 → 패턴으로 되돌리기"는 만들지 않는다.
- 음높이 표시 범위는 클립의 기존 음을 포함하므로(§2.1) 굽기로 생긴 음이 화면에서 잘리지 않는다.

## 9. 완료 기준

1. `pnpm lint`, `pnpm check-types`, `pnpm test`, `pnpm build` 통과.
2. `notes.ts`의 모든 규칙에 테스트가 있고 속성 테스트가 있다(변이 검증 기록).
3. 컴포넌트·통합 시나리오 통과(§6), 제스처 취소 경로와 카운터 누수 검사 포함.
4. 실제 Chrome에서 굽기 → 음 편집(추가·선택·이동·길이·세기·키보드) → 재생·정지 → 되돌리기 → 새로고침 복원을 조작해 확인하고 결과를 기록한다.
5. 사용자가 듣기 확인(체크리스트를 `docs/known-gaps.md`에 갱신).
6. 문서 갱신(AGENTS.md 상태·"아직 없는 것", README, known-gaps, ui-conventions의 제스처 표, 이 설계의 상태).
