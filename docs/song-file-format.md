# 곡 파일 형식 (`.json`)

Bandline의 `⭳ 저장` 버튼이 만들고 `⭱ 불러오기` 버튼이 읽는 파일의 형식이다.

일반 JSON이라 텍스트 편집기로 열어 고칠 수 있다. 이 문서는 **무엇을 고쳐도 되고 무엇을 고치면 거부되는지**를 정리한다.

- 형식 정의: `lib/score/schema.ts`
- 읽기/쓰기: `lib/score/serialize.ts`
- 설계 근거: [`docs/superpowers/specs/2026-08-02-song-file-io-design.md`](superpowers/specs/2026-08-02-song-file-io-design.md)

## 한눈에 보기

```json
{
  "format": "bandline-song",
  "version": 1,
  "song": {
    "tempo": 120,
    "timeSignature": [4, 4],
    "lengthTicks": 30720,
    "lines": [
      {
        "id": "line-piano",
        "name": "피아노",
        "kind": "pitched",
        "instrument": "piano",
        "tiles": [
          { "id": "piano-0", "start": 0, "length": 1920, "velocity": 0.7, "notes": [60, 64, 67] }
        ]
      },
      {
        "id": "line-drums",
        "name": "드럼",
        "kind": "drum",
        "instrument": "drums",
        "tiles": [
          { "id": "kick-0", "start": 0, "length": 120, "velocity": 0.9, "notes": [36] }
        ]
      }
    ]
  }
}
```

## 최상위 봉투

| 필드 | 타입 | 값 |
| --- | --- | --- |
| `format` | string | 반드시 `"bandline-song"` |
| `version` | number | 반드시 `1` |
| `song` | object | 곡 본체 |

`format`은 "이게 Bandline 파일인가"를 판별한다. 아무 JSON이나 열었을 때 필드 이름을 늘어놓는 대신 `Bandline 곡 파일이 아닙니다.`라고 말할 수 있는 건 이 필드 덕분이다.

`version`이 `1`이 아니면 **무조건 거부한다.** 큰 값은 모르는 형식이고, 작은 값은 존재한 적이 없다. 어느 쪽이든 추측해서 열면 곡이 조용히 망가진다.

## `song`

| 필드 | 타입 | 제약 |
| --- | --- | --- |
| `tempo` | number | BPM. 40~240 밖이면 **잘라서 받는다** |
| `timeSignature` | `[number, number]` | 양의 정수 둘. 예: `[4, 4]`, `[3, 4]` |
| `lengthTicks` | number | 곡 전체 길이(틱). 120 이상 960000 이하 |
| `lines` | array | 최소 1개. 라인 `id`는 서로 달라야 한다 |

`lengthTicks`의 상한 960000은 4/4 기준 500마디다. 음악적 제한이 아니라 **렌더 비용 가드**다 — `lengthTicks: 1000000000` 같은 값이 들어오면 눈금자를 그리는 것만으로 탭이 멈춘다.

## `lines[]`

| 필드 | 타입 | 제약 |
| --- | --- | --- |
| `id` | string | 빈 문자열 불가. 곡 안에서 유일 |
| `name` | string | 화면에 보이는 이름. 아무 값이나 가능 |
| `kind` | `"pitched"` \| `"drum"` | 어느 UI로 그릴지 결정 |
| `instrument` | `"piano"` \| `"guitar"` \| `"bass"` \| `"drums"` | 어떤 소리를 낼지 결정 |
| `tiles` | array | 빈 배열 허용. 타일 `id`는 **그 라인 안에서** 유일 |

**`kind`와 `instrument`는 짝이 맞아야 한다.**

```text
kind: "drum"     ⟺  instrument: "drums"
kind: "pitched"  ⟺  instrument: "piano" | "guitar" | "bass"
```

어긋나면 거부한다. 섞으면 편집기가 만들 수는 있지만 **지울 수는 없는** 유령 타일이 생기기 때문이다.

타일 `id`는 라인이 다르면 겹쳐도 된다. 편집 함수가 항상 라인까지 함께 보므로 충돌하지 않는다.

## `tiles[]`

타일 하나가 "언제부터 얼마나, 어떤 음을, 얼마나 세게" 울릴지를 담는다.

| 필드 | 타입 | 제약 |
| --- | --- | --- |
| `id` | string | 빈 문자열 불가. 라인 안에서 유일 |
| `start` | number | 곡 시작 기준 절대 틱. 정수 |
| `length` | number | 울리는 길이(틱). 정수 |
| `velocity` | number | 세기. 0~1 밖이면 **잘라서 받는다** |
| `notes` | number[] | 최소 1개. 각 값은 0~127 정수 |

`notes`에 여러 값을 넣으면 **동시에** 울린다 — 화음이다.

**타일이 겹쳐도 된다.** 버그가 아니라 기능이다. 화음 안의 음마다 길이나 세기를 다르게 주고 싶으면 같은 자리에 타일을 겹쳐 놓는다.

## 시간 단위 — 틱

모든 시간은 **틱(tick)** 정수다. 초가 아니다. 초로 저장하면 템포를 바꾸는 순간 곡 전체가 어긋난다.

```text
PPQ = 480      4분음표 하나 = 480틱
```

| 음표 | 틱 | 4/4 기준 |
| --- | --- | --- |
| 온음표 | 1920 | 한 마디 |
| 4분음표 | 480 | 한 박 |
| 8분음표 | 240 | |
| 16분음표 | 120 | 편집 격자 한 칸 · 타일 최소 길이 |

마디 수 → 틱 환산 (4/4):

```text
lengthTicks = 마디 수 × 1920
16마디 = 30720      64마디 = 122880
```

박자표가 4/4가 아니면 한 마디 = `PPQ × 4 ÷ 분모 × 분자`다. 3/4이면 `480 × 4 ÷ 4 × 3 = 1440`.

## 음 번호

음정 라인(`kind: "pitched"`)은 **MIDI 번호**를 쓴다.

| 번호 | 음 |
| --- | --- |
| 60 | C4 (가운데 도) |
| 62 | D4 |
| 64 | E4 |
| 67 | G4 |
| 72 | C5 (한 옥타브 위) |

반음 하나가 1이다. 옥타브는 12.

드럼 라인(`kind: "drum"`)은 **GM 드럼 번호**를 쓴다. 편집기가 다루는 건 셋뿐이다.

| 번호 | 악기 |
| --- | --- |
| 36 | 킥 |
| 38 | 스네어 |
| 42 | 하이햇 |

드럼 타일은 격자 한 칸(120틱)이 기본이고 `notes`에 값 하나만 넣는 것이 정상이다.

## 검증 — 거부하는 것

하나라도 걸리면 파일을 열지 않고 이유를 화면에 띄운다.

| 조건 | 이유 |
| --- | --- |
| JSON으로 파싱 안 됨 | 파일이 아니다 |
| `format`이 다름 | 우리 파일이 아니다 |
| `version`이 1이 아님 | 모르는 형식이다 |
| 필드 누락 · 타입 불일치 | 무엇을 의도했는지 알 수 없다 |
| `NaN` · `Infinity` | 이후 계산이 전부 무너진다 |
| `kind` / `instrument`가 목록 밖 | 그릴 UI도 낼 소리도 없다 |
| `kind`와 `instrument` 불일치 | 지울 수 없는 유령 타일이 생긴다 |
| `notes`가 빈 배열 | 소리 안 나는 타일은 화면만 차지한다 |
| `notes` 값이 0~127 밖 | MIDI 범위 밖 |
| `lines`가 빈 배열 | 라인 추가 UI가 아직 없어 복구 불가 |
| `lengthTicks`가 120 미만 또는 960000 초과 | 타일이 안 들어가거나 렌더가 멈춘다 |
| 라인 `id` 중복 | 두 번째 라인이 영원히 편집 안 된다 |
| 한 라인 안 타일 `id` 중복 | 같은 이유 |

에러 문구에는 위치가 함께 나온다.

```text
파일이 손상되었습니다 (lines[0].tiles[3].velocity)
```

## 검증 — 조용히 고치는 것

의도가 분명한 값은 거부하지 않고 고쳐서 받는다.

| 조건 | 처리 |
| --- | --- |
| `start` · `length` · `lengthTicks`가 소수 | 반올림 |
| `velocity`가 0~1 밖 | 0 또는 1로 자름 |
| `tempo`가 40~240 밖 | 자르고 반올림 |
| `length`가 120 미만 | 120으로 올림 |
| 타일이 곡 밖으로 나감 | 경계 안으로 당김 |
| `tiles`가 `start` 순서가 아님 | 정렬 |

**정렬은 특히 중요하다.** 재생 스케줄러가 `tiles` 배열의 인덱스를 커서로 쓰기 때문에, 순서가 어긋난 곡은 재생 중 노트가 **조용히 누락된다.** 에러도 로그도 없다. 그래서 불러올 때마다 무조건 정렬한다.

`notes`의 음높이만은 자르지 않고 거부한다. 세기를 자르면 소리 크기만 달라지지만, 음높이를 자르면 곡이 조용히 다른 곡이 되기 때문이다.

## 손으로 고칠 때

되는 것:

- `tempo`, `velocity` 같은 숫자 바꾸기
- `notes` 값 바꾸기 (0~127 안에서)
- 타일 추가·삭제 — `id`만 그 라인 안에서 유일하면 된다
- `name` 바꾸기
- `tiles` 순서 뒤섞기 — 불러올 때 정렬된다

주의할 것:

- **라인 `id`를 바꾸면** 그 라인의 타일 `id`까지 손볼 필요는 없지만, `lines` 안에서 유일해야 한다
- **`kind`를 바꾸면 `instrument`도 함께** 바꿔야 한다
- `lengthTicks`를 줄이면 그 밖으로 나간 타일이 경계로 끌려온다 — 지워지지는 않지만 위치가 바뀐다

## 최소 예시

복사해서 `.json`으로 저장하면 바로 열린다. 4/4, 120 BPM, 2마디, 피아노 한 라인.

```json
{
  "format": "bandline-song",
  "version": 1,
  "song": {
    "tempo": 120,
    "timeSignature": [4, 4],
    "lengthTicks": 3840,
    "lines": [
      {
        "id": "line-piano",
        "name": "피아노",
        "kind": "pitched",
        "instrument": "piano",
        "tiles": [
          { "id": "t0", "start": 0,    "length": 480, "velocity": 0.7, "notes": [60, 64, 67] },
          { "id": "t1", "start": 480,  "length": 480, "velocity": 0.7, "notes": [62, 65, 69] },
          { "id": "t2", "start": 960,  "length": 480, "velocity": 0.7, "notes": [64, 67, 71] },
          { "id": "t3", "start": 1440, "length": 480, "velocity": 0.7, "notes": [65, 69, 72] }
        ]
      }
    ]
  }
}
```

## 형식이 바뀌면

`version`을 올리고 구버전 파일을 읽는 경로를 만든다. 지금은 `1`뿐이라 변환 코드가 없다.

필드를 더할 때는 `lib/score/types.ts`(타입)와 `lib/score/schema.ts`(검증)를 함께 고쳐야 한다. 한쪽만 고치면 타입에는 있는데 검증에서 떨어지거나 그 반대가 된다.
